# 專題初始計畫大綱：Discord AI 託管服務客服系統

## 一、研究動機與目標

本專題將在已公司化營運的託管服務中進行實驗，以實際客服需求作為開發與驗證的依據。實驗驗證成功後，系統將正式上線，應用於日常客服工作。

託管服務的客戶會透過 Discord 詢問帳務、伺服器狀態與使用問題。人工客服除了回覆訊息，也需要反覆查詢資料、核對設定及排查問題。這些工作步驟繁瑣，客服不一定能即時處理，接手時也需要重新閱讀對話。

本專題計畫建立 AI 輔助客服系統，讓 AI 釐清問題後，透過工具調用完成繁瑣、重複且低風險的處理流程，例如查詢服務狀態、收集必要的診斷資訊及核對常見設定。系統會檢查處理結果，再向客戶說明；遇到超出能力或權限的問題，則整理已嘗試的步驟，交由人工接手。

## 二、預計功能

- 在既有 Discord 客服單機器人中提供 AI 客服。
- 根據 Discord 身分確認對應的 WHMCS 客戶與服務。
- 查詢 Pterodactyl 伺服器狀態，提供基本排查建議。
- 依問題串接多個受控工具，處理常見的重複工作，並確認執行結果。第一階段以唯讀查詢與診斷為主，後續再加入經安全評估的低風險操作。
- 產生交班摘要，人工接手後停止自動回覆。

訂單審核列為後續擴充；退款、終止服務與備份還原不交由 AI 執行。

## 三、系統架構與技術

Discord 客服單機器人負責客服入口與客服單管理，AI 負責對話、選擇工具及安排處理步驟，Support Core 負責身分、服務所有權與操作權限檢查。可執行的工具與安全條件由程式預先定義，需要確認的操作須取得客戶或工作人員同意，不能由 AI 自行認定安全。

WHMCS 提供客戶及服務資料，Pterodactyl 提供伺服器狀態。後端採用 TypeScript、Node.js 與 API 串接。AI 執行框架前期曾考慮 Hermes，目前暫以 OpenClaw 為候選，最終選型將透過原型測試，比較工具調用、權限控制、Discord 整合及維護成本。Support Core 保持獨立，方便後續替換 AI 執行框架。第一版不另建客戶資料庫，也不加入 Redis。

## 四、開發與驗證步驟

1. 確認 Discord 與 WHMCS 的身分查詢介面及錯誤行為。
2. 完成客戶身分、服務所有權與伺服器狀態的唯讀查詢。
3. 建立常見問題的工具處理流程，串接 Discord 對話、交班摘要與人工接手功能。
4. 使用測試帳號驗證工具處理結果、回答內容、摘要品質及權限隔離，記錄任務完成情況、回應時間與失敗原因；工具失敗或權限不足時，不得繼續執行受限操作。

## 五、預期成果與目前進度

預期交付可展示的客服原型、程式碼、架構文件與測試報告，示範「客戶提問、AI 調用工具處理問題、確認結果、回覆客戶或交由人工接手」的完整流程，並評估哪些重複工作能在權限與安全限制內由系統完成。

目前已完成專案基礎架構與身分查詢測試工具；WHMCS API 的實際回應仍待驗證，正式 AI 客服及伺服器串接尚未完成。
