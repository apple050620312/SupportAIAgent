# 專題初始計畫大綱：Discord AI 託管服務客服系統

## 一、研究動機與目標

託管服務的客戶會透過 Discord 詢問帳務、伺服器狀態與使用問題。人工客服不一定能即時回覆，接手時也需要重新閱讀對話。

本專題計畫建立 AI 輔助客服系統，先回應客戶、釐清問題並查詢相關服務資料。需要人工處理時，系統整理問題與已嘗試的處理方式，協助客服接手。

## 二、預計功能

- 在既有 Discord Ticket Bot 中提供 AI 客服。
- 根據 Discord 身分確認對應的 WHMCS 客戶與服務。
- 查詢 Pterodactyl 伺服器狀態，提供基本排查建議。
- 產生交班摘要，人工接手後停止自動回覆。

訂單審核列為後續擴充；退款、終止服務與備份還原不交由 AI 執行。

## 三、系統架構與技術

Discord Ticket Bot 負責客服入口與工單管理，AI 負責對話及問題整理，Support Core 負責身分、服務所有權與操作權限檢查。

WHMCS 提供客戶及服務資料，Pterodactyl 提供伺服器狀態。後端採用 TypeScript、Node.js 與 API 串接；AI 執行框架暫以 OpenClaw 為候選。第一版不另建客戶資料庫，也不加入 Redis。

## 四、開發與驗證步驟

1. 確認 Discord 與 WHMCS 的身分查詢介面及錯誤行為。
2. 完成客戶身分、服務所有權與伺服器狀態的唯讀查詢。
3. 串接 Discord 對話、交班摘要與人工接手流程。
4. 使用測試帳號驗證回答內容、摘要品質及權限隔離，記錄回應時間與失敗情況。

## 五、預期成果與目前進度

預期交付可展示的客服原型、程式碼、架構文件與測試報告，示範「客戶提問、查詢資料、整理問題、人工接手」的完整流程。

目前已完成專案基礎架構與身分查詢測試工具；WHMCS API 的實際回應仍待驗證，正式 AI 客服及伺服器串接尚未完成。
