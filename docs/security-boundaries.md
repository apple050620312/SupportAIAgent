# Security Boundaries

OpenClaw is an orchestration and agent layer, not the final authorization boundary. Support Core and its trusted integration adapters own identity resolution, ownership checks, authorization, and policy enforcement.

Support Core must never trust customer IDs, claims of service ownership, Pterodactyl server UUID ownership, or authorization decisions generated by a model. Every customer-specific operation must follow:

```text
Discord actor
  -> resolve linked WHMCS customer
  -> resolve owned WHMCS services
  -> resolve corresponding Pterodactyl resource
  -> authorize operation
  -> perform operation
```

A model-provided identifier is only a selector within resources already proven to belong to the resolved customer. It is not ownership evidence. Failures must fail closed, including ambiguous mappings and unavailable upstreams.

WHMCS and Pterodactyl privileged credentials remain inside their adapters. They must never be exposed to the model, Discord, shared contracts, error details, or logs. The agent must not receive arbitrary HTTP, arbitrary provider API, refund, termination, deletion, or destructive restore capabilities.

Correlation IDs are operational metadata, not authentication. Identity transport and service-to-service authentication between OpenClaw and Support Core remain intentionally unspecified until a later task.
